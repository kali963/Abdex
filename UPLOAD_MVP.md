# Как загрузить существующий MVP в этот репозиторий

RAR-архив большой, потому что в нём почти наверняка лежат виртуальное окружение (`venv`), `node_modules`,
кэши, база данных и загруженные пользователями файлы. В репозиторий нужен только исходный код. Скрипты ниже
сами всё это отбрасывают, поэтому загружать придётся в десятки раз меньше.

MVP попадёт в **отдельную ветку `mvp-original`**, в папку `legacy/mvp/`. Новая платформа при этом
не затрагивается. После загрузки я сравню MVP с новой платформой и перенесу всё нужное (реальные
сценарии, данные справочников, настройки).

---

## Вариант 1. Windows: скрипт (рекомендую)

1. Установите Git, если его ещё нет: <https://git-scm.com/download/win> (все параметры по умолчанию).
2. Распакуйте RAR в отдельную папку, например `C:\abdex-mvp`.
3. Скачайте скрипт `scripts/upload_mvp.ps1` из этого репозитория
   (на GitHub откройте файл → кнопка **Download raw file**).
4. Откройте PowerShell в папке со скриптом и выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\upload_mvp.ps1 -Source "C:\abdex-mvp"
   ```

5. Если Git спросит логин, откроется окно входа в GitHub: войдите под аккаунтом, у которого есть доступ к репозиторию.

Что делает скрипт:
- клонирует репозиторий в `%USERPROFILE%\abdex-upload` и создаёт ветку `mvp-original`;
- копирует проект в `legacy/mvp`, **исключая** `venv`, `node_modules`, `__pycache__`, `.git`,
  `media`, `uploads`, `*.db`, `*.sqlite3`, архивы, логи и секреты (`.env`, `*.pem`, `*.key`);
- убирает файлы больше 95 МБ (GitHub не принимает файлы больше 100 МБ) и показывает их список;
- ищет в коде пароли или ключи. Если находит, показывает строки и спрашивает, продолжать ли;
- делает коммит и отправляет ветку на GitHub.

## Вариант 2. macOS / Linux: скрипт

```bash
unrar x abdex.rar ~/abdex-mvp/          # или распакуйте любым архиватором
bash scripts/upload_mvp.sh ~/abdex-mvp
```

## Вариант 3. GitHub Desktop (без командной строки)

1. Установите [GitHub Desktop](https://desktop.github.com/) и войдите в аккаунт.
2. **File → Clone repository** → `kali963/Abdex`.
3. **Branch → New branch** → `mvp-original` (на основе `main`).
4. В папке клонированного репозитория создайте `legacy\mvp` и скопируйте туда проект из RAR.
   **Не копируйте** папки `venv`, `.venv`, `env`, `node_modules`, `__pycache__`, `.git`, `media`, `uploads`,
   файлы `.env`, `*.db`, `*.sqlite3`. В этом репозитории уже есть `.gitignore`, который их отсекает.
5. Введите описание коммита (Summary) → **Commit to mvp-original** → **Publish branch**.

## Почему не через загрузку на сайте GitHub

Загрузка через браузер (Add file → Upload files) принимает до 100 файлов за раз и файлы до 25 МБ,
поэтому проект целиком так не загрузить. Для отдельных файлов этот способ подходит.

## Важно про данные и секреты

- **Не загружайте реальную базу данных и файлы пользователей** (сканы документов, фото). Это персональные
  данные, и по ТЗ (SEC-DAT-09, NFR-LAW-01) их нельзя хранить в репозитории. Если нужны примеры данных,
  сделайте обезличенный дамп.
- **Не загружайте `.env`, пароли и ключи.** Если они раньше были в коде MVP, после загрузки их нужно сменить
  (ротация), потому что история Git хранит всё.

## После загрузки

Напишите мне: «MVP загружен в ветку mvp-original». Я:
1. разберу, что работает в MVP и что держится на ручных действиях (п. 57.4 ТЗ «Что делать в первую неделю»);
2. перенесу в новую платформу реальные сценарии, справочники и настройки из MVP;
3. подготовлю план миграции данных из старой базы, если она есть.
