# Эксплуатация (OPS-06)

## Развёртывание
1. Соберите образ: `docker build -t abdex:<версия> .`
2. Переменные окружения перечислены в `.env.example`. Обязательные для production: `APP_ENV=production`,
   `SECRET_KEY` (из хранилища секретов), `DATABASE_URL`, `ADMIN_HOST`.
3. Миграции применяются при старте контейнера (`scripts/docker-entrypoint.sh`). Каждая миграция обратима
   (`alembic downgrade -1`) и должна быть совместима с предыдущей версией кода (OPS-04).
4. Фоновый обработчик запускается отдельным контейнером: `python -m app.worker`. В веб-контейнере
   задайте `RUN_BACKGROUND_WORKER=false`.

## Откат релиза (не дольше 15 минут)
`docker compose up -d app=<предыдущий тег>`. Если релиз добавил миграцию, сначала `alembic downgrade <ревизия>`.

## Резервное копирование (OPS-05)
- Ежедневная полная копия: `pg_dump -Fc`. Плюс непрерывная архивация WAL (`archive_mode=on`).
- Копии шифруются и хранятся отдельно от рабочей среды, на территории РК. Срок хранения не меньше 30 дней.
- Раз в квартал проводится пробное восстановление на отдельном стенде и оформляется акт.

## Проверка работоспособности
`GET /healthz` проверяет приложение и соединение с БД.

## Журналы
Логи в формате JSON идут в stdout, у каждой записи есть `request_id` (тот же код показывается пользователю на
странице ошибки). Пароли, коды, токены, IBAN и ИИН в журнал не попадают (`core/audit.mask`).
