# Запуск AbdEX в бою — пошагово

Порядок проверен на боевом стеке: HTTPS, PostgreSQL с отдельной ролью и RLS, Redis, ClamAV, NCANode,
регистрация с SMS-кодом, вход администратора с 2FA, восстановление пароля, общие лимиты попыток.

## 0. Что нужно заранее

| Что | Зачем | Где |
|---|---|---|
| Сервер **в Казахстане**: 4 vCPU, 8 ГБ RAM, 80 ГБ SSD, Ubuntu 22.04/24.04 | закон о персональных данных требует хранить ПДн граждан РК на территории РК; Vercel и зарубежные облака для боя не подходят | PS.kz, Hoster.kz, Kazteleport, QazCloud и др. |
| Домен и 2 DNS-записи A: `abdex.kz`, `admin.abdex.kz` → IP сервера | сайт и отдельный адрес админки | регистратор .kz |
| SMS-провайдер: Mobizon.kz или SMSC.kz (договор, API-ключ, имя отправителя) | коды регистрации и входа — **без SMS клиенты не зарегистрируются** | mobizon.kz / smsc.kz |
| Почтовый ящик для отправки (SMTP) | счета, акты, восстановление пароля по e-mail | любой почтовый сервис |
| Хранилище для копий вне сервера (в РК) | резервные копии | второй сервер / объектное хранилище |
| Для ЭЦП через eGov mobile — тариф SIGEX (сразу) или заявка в Smart Bridge (позже) | см. `docs/eds-setup.md` | sigex.kz / smartbridge.egov.kz |
| Уведомление уполномоченного органа о сборе ПДн, политика ПДн и оферта на сайте | закон РК о ПДн | юрист |

## 1. Подготовка сервера

```bash
# Docker
curl -fsSL https://get.docker.com | sh
# брандмауэр: снаружи только SSH, HTTP, HTTPS
ufw allow OpenSSH && ufw allow 80,443/tcp && ufw allow 443/udp && ufw enable
# код
git clone https://github.com/kali963/Abdex.git /opt/abdex && cd /opt/abdex/deploy
```

## 2. Секреты и настройки

```bash
sudo sh generate-secrets.sh          # ключ шифрования ПДн + строки для .env.production
cp .env.production.example .env.production
nano .env.production                  # домены, сгенерированные значения, SMS, SMTP
```

**Сохраните копию `deploy/secrets/field_keys` и `.env.production` в надёжном месте вне сервера.** Без ключа
шифрования зашифрованные поля (ИИН, IBAN, телефоны водителей) прочитать невозможно — ни вам, ни нам.

## 3. Запуск

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
docker compose -f docker-compose.prod.yml --env-file .env.production ps     # все Up, app — healthy
```

При первом запуске: создаётся база и роль приложения (без прав суперпользователя — защита строк RLS
действует по-настоящему), применяются миграции, Caddy получает сертификаты Let's Encrypt (1–2 минуты),
ClamAV загружает антивирусные базы (несколько минут; до этого загрузка файлов отвечает «попробуйте позже»).

Если в настройках чего-то не хватает, приложение **не запустится** и напишет в журнал, чего именно:
`docker compose -f docker-compose.prod.yml logs app | tail -30`.

## 4. Первый администратор

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec app \
  python -m app.cli create-staff --phone +77010000000 --name "Имя Фамилия" --role admin --email you@abdex.kz
```

Команда выведет одноразовый пароль. Вход — на `https://admin.abdex.kz/login`. При первом входе админка
потребует включить приложение-аутентификатор (Google Authenticator, Яндекс Ключ и т. п.): «Безопасность» →
отсканировать QR → ввести код. Затем смените пароль. Других сотрудников добавляйте той же командой с ролью
`manager`, `moderator`, `finance` или `auditor`.

## 5. Проверка готовности

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec app python -m app.cli preflight
```

Должно быть `0 error(s)`. Предупреждения (warn) прочитайте и закройте те, что относятся к вам.

Ручная проверка (15 минут):
1. Регистрация заказчика с телефоном — код пришёл SMS, вход выполнен.
2. Регистрация перевозчика; загрузка документов на проверку; модератор в админке одобряет.
3. Заявка → предложение → выбор → договор-заявка → подписание кодом из SMS обеими сторонами.
4. «Забыли пароль» — ссылка в SMS открывается и меняет пароль.
5. В админке: модерация, финансы, флаги функций открываются.

## 6. Резервные копии

```bash
apt install -y gnupg
crontab -e
# 15 3 * * *  /opt/abdex/deploy/backup.sh >> /var/log/abdex-backup.log 2>&1
```

Копии шифруются (`BACKUP_PASSPHRASE`) и хранятся 30 дней в `/var/backups/abdex`. Настройте копирование
этого каталога на хранилище вне сервера (rclone/rsync) и **раз в квартал проверяйте восстановление** на
отдельном сервере: `./restore.sh <db-…dump.gpg> [<storage-…tar.gpg>]`.

## 7. Мониторинг

* `https://abdex.kz/healthz` — внешняя проверка доступности (UptimeRobot, Zabbix и т. п.) раз в минуту.
* `https://abdex.kz/metrics` с заголовком `Authorization: Bearer <METRICS_TOKEN>` — метрики для Prometheus.
* Журналы: `docker compose -f docker-compose.prod.yml logs -f app worker` (JSON, без паролей и кодов).
* Админка → KPI и журнал интеграций: ошибки SMS, ЭЦП, платежей.

## 8. Обновление версии

```bash
cd /opt/abdex && git pull
cd deploy && ./backup.sh                                  # копия перед обновлением
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

Миграции применяются автоматически при старте. Откат: `git checkout <предыдущий тег>` и та же команда; если
релиз добавлял миграцию — сначала `docker compose ... exec app alembic downgrade <ревизия>`.

## 9. Нагрузка

Нагрузочный тест боевого стека (всё на одной машине 4 vCPU вместе с генератором нагрузки, страницы
личного кабинета через HTTPS): 50 одновременных пользователей — около 200 запросов в секунду без ошибок,
95 % ответов быстрее 0,5 с. При перегрузке запросы встают в очередь, а если ждать слишком долго — пользователь
видит «Сервер перегружен, обновите страницу» (503), а не ошибку.

При росте: увеличьте `WEB_CONCURRENCY` (≈ 2 × ядра) и при необходимости `DB_POOL_SIZE`/`DB_MAX_OVERFLOW`
(следите за суммой относительно `max_connections` PostgreSQL), вынесите PostgreSQL на отдельный сервер,
добавьте реплику для отчётов (`ANALYTICS_DATABASE_URL`).

## Что подключается позже (сайт работает и без этого)

| Функция | Пока не подключено | Что происходит |
|---|---|---|
| ЭЦП (NCALayer, eGov) | флаги выключены | подписание кодом из SMS |
| Проверка компании в госреестре | нет договора с поставщиком данных | проверку делает модератор вручную |
| Биометрия водителя | нет лицензированного провайдера | модератор проверяет по документам |
| ЭТТН, ЭСФ | нет шлюза | документы формируются, загрузка вручную |
| Онлайн-оплата | нет договора с банком/эквайером | оплата по счёту, отметка бухгалтером |
| Push в браузере | нет `VAPID_PRIVATE_KEY` | уведомления на сайте, SMS, Telegram, e-mail |
