# ЭЦП: NCALayer, eGov mobile, eGov Business — запуск

Подписи НУЦ РК на платформе работают тремя способами, и все проверяются на сервере одинаково (GOV-DS-02):
целостность, цепочка до корневого сертификата НУЦ, срок действия на момент подписи, отзыв (OCSP) и
принадлежность БИН/ИИН компании.

| Способ | Где ключ | Что делает пользователь |
|---|---|---|
| NCALayer | файл `.p12`, Казтокен, ID-карта на компьютере | нажимает «Подписать ЭЦП», выбирает ключ и вводит пароль в окне NCALayer |
| eGov mobile | личная ЭЦП в телефоне | нажимает «Подписать в eGov mobile», сканирует QR в приложении, подтверждает |
| eGov Business | ЭЦП компании в телефоне | то же, в приложении eGov Business |

Договоров с НУЦ или eGov для этого не нужно: NCALayer и проверка через NCANode используют публичные службы
НУЦ (OCSP, TSP, CRL), протокол QR-подписания eGov mobile открыт. Перед запуском в бою стоит одним письмом
уточнить в поддержке eGov mobile (АО «НИТ»), не требуется ли регистрация сервиса, — правила меняются.

## 1. Сервис проверки подписи (NCANode)

```bash
docker compose --profile eds up -d ncanode
```

В `.env`:

```
EDS_NCANODE_URL=http://ncanode:14579
```

NCANode должен иметь выход в интернет к `ocsp.pki.gov.kz`, `tsp.pki.gov.kz`, `crl.pki.gov.kz`, но сам
наружу не публикуется — к нему обращается только приложение. Без `EDS_NCANODE_URL` в production подпись не
принимается (в разработке работает тестовый УЦ).


## 2. Публичный адрес

eGov mobile скачивает документ с сайта, поэтому сайт должен быть доступен из интернета по HTTPS:

```
PUBLIC_BASE_URL=https://abdex.kz
```

QR-код содержит ссылку `mobileSign:https://abdex.kz/egov/mgov/<одноразовый токен>`; ссылка живёт 5 минут и
срабатывает один раз. Документ отдаётся приложению только по токену и выведенному из него ключу доступа.

## 3. Включить в админке (/admin → Флаги)

* `qualified_signature` — подписание документов сделки ЭЦП (NCALayer); можно включать по компаниям;
* `eds.egov_mobile` — подписание документов сделки в eGov mobile / eGov Business по QR;
* `auth.eds_login` — вход по ЭЦП через NCALayer;
* `auth.egov_mobile` — вход через eGov mobile по QR.

Для входа по ЭЦП пользователь один раз привязывает ЭЦП в «Безопасность» — после этого ИИН из сертификата
сопоставляется с аккаунтом.

## 4. Пользователям

* **NCALayer** — скачать с https://pki.gov.kz/ncalayer/, установить и запустить (значок в трее). Если
  NCALayer не запущен, сайт показывает ссылку на установку. Для входа используется ключ AUTH, для подписи
  документов — ключ подписи (RSA/GOST).
* **eGov mobile / eGov Business** — в приложении «Сканировать QR» и подтвердить подпись. Документ компании
  подписывает сотрудник с ЭЦП этой компании (проверяется БИН в сертификате).

## 5. Проверка перед запуском

1. Вход через NCALayer ключом AUTH физлица, привязанного к аккаунту.
2. Подписание договора-заявки ключом подписи юрлица через NCALayer — на странице «Подписи» все проверки ✓.
3. То же через eGov Business по QR.
4. Попытка подписать ключом чужой компании — отказ «owner».
5. Повторная проверка подписи (кнопка на странице «Подписи») — проходит.

## Разработка

Без `EDS_NCANODE_URL` и не в production вместо NCALayer ключ создаётся в браузере (WebCrypto) и
заверяется тестовым УЦ, а под QR-кодом есть кнопка «Тестовый телефон», которая играет роль eGov mobile.
