# Демо на Vercel: подключение PostgreSQL

## Почему без базы «выкидывает» на вход

Vercel запускает сайт как бессерверную функцию: одновременно работает несколько экземпляров, и каждый
новый экземпляр стартует с нуля. Без `DATABASE_URL` каждый из них создаёт свою временную базу SQLite в
`/tmp` со своими демо-данными. Вход сохраняется в базе того экземпляра, который его обработал, а следующий
клик может попасть на другой экземпляр, где такой сессии нет, — и сайт отправляет на страницу входа. По
той же причине пропадают созданные заявки и любые изменения.

Пока база не подключена, на каждой странице показывается жёлтое предупреждение.

## Как исправить (5 минут, бесплатно)

1. Vercel → проект → вкладка **Storage** → **Create Database** → **Neon** (Serverless Postgres) →
   выбрать бесплатный план и регион поближе (например, Frankfurt) → **Connect** к проекту для всех окружений
   (Production, Preview, Development).
   Vercel сам добавит переменные `DATABASE_URL`, `POSTGRES_URL` и другие — сайт подхватит любую из них.
2. Проект → **Settings → Environment Variables** → добавить `SECRET_KEY` — длинная случайная строка
   (например, результат `python -c "import secrets; print(secrets.token_urlsafe(48))"`).
3. **Deployments** → последний деплой → **Redeploy**.

При первом запуске сайт сам создаст таблицы и демо-данные; если стартуют сразу несколько экземпляров, это
делает один, остальные ждут. После этого вход, переходы по админке и все изменения общие для всех
экземпляров.

Проверка: жёлтое предупреждение «Демо-стенд без постоянной базы данных» исчезло; вход под администратором
сохраняется при переходах по разделам.

## Ограничения Vercel

* WebSocket не поддерживается — чат сделки автоматически работает через опрос раз в несколько секунд.
* Фоновые задачи (рассылки, повторы вебхуков, ЭСФ) не выполняются: для боевой работы нужен обычный сервер
  (`docker compose up`, см. `docs/operations.md`).
* Загруженные файлы хранятся в `/tmp` экземпляра и тоже не общие. Для демо это допустимо; для боевой работы —
  сервер с постоянным диском или объектное хранилище.
